# 业界参考实现与标准 · 学习资料总览

> 这套材料的用途：把**你已经在这个仓库里自己实现过的东西**（单线 LiDAR 感知、HD Map 背景减除、
> Frenet 横纵解耦规划、走廊/裕度、物体层聚类跟踪、跟驰）对接到**业界的标准做法与标准文档**上，

>
> 读者画像：编程经验丰富、算法初学者（本仓库作者）。
> 所有材料都以**能回连到本仓库的具体文件**为前提撰写 —— 看到任何概念，都应该能在
> `js/algo/`、`js/env/`、`js/mapgen/` 里找到对应的（或缺失的）那一块。

## 二、推荐学习路线（按性价比，不是按学科顺序）

### 阶段 0：先补"缺口最大"的两件（各半天）

1. **[05 多目标跟踪](./05-多目标跟踪-MOT.md) 的滤波与关联部分** —— 你已经写了 `objects.ts`，
   先知道自己的 α-β + 最近邻在学界叫什么、什么时候会失效（模式切换、近邻抢测量、ID 保持）。
   → 直接收益：理解"同一辆车裂成两个物体"（你实测的**幽灵双胞胎**）为什么是 MOT 经典问题。
2. **[02 地图标准](./02-地图标准-lanelet2-opendrive.md) 的车道归属部分** —— 你的**幽灵刹车**根因
   就是"逐点投影 + |l| 比值"判断归属；业界用**车道多边形 + 物体框 + 置信度/迟滞**。
   → 直接收益：知道该把"归属判断"从几何反推改成物体级判据。

### 阶段 1：把规划器对接到业界框架（1~2 天）

3. **[03 RSS](./03-责任划分-rss.md)** —— "不在我的行驶车道 ⇒ 我无让行义务"就是 lateral proper response；
   切入（cut-in）为什么要单独处理而不是几何膨胀的副产物。
   → 直接收益：你的走廊膨胀语义会变得可解释、可辩论。
4. **[06 规划与控制](./06-规划与控制-业界参考.md)** —— EM Planner 的迭代、行为决策分层、
   "舒适层 → 安全门 → 紧急制动"的三层兜底。
   → 直接收益：知道你现在的 `EMERGENCY` + 可达性闸门在业界属于哪一层、缺哪一层。

### 阶段 2：补上最大的代差（2~3 天）

5. **[04 预测](./04-预测-数据集与基准.md)** —— 先实现**常速度 + 车道跟随**的最小预测（几小时），
   再把 ST 层从"静态矩形"改成"随时间占用"。
   → 直接收益：车流密集时的爬行 / 走走停停 / EMERGENCY 会从根上改善（这是你文档里记着的
   "静态障碍假设"）。

### 阶段 3：系统视角（按需查阅）

6. **[01 开源栈](./01-开源栈-apollo-autoware.md)** —— 把这六篇放回一张完整架构图里：
   传感器同步 → 感知 → 融合跟踪 → 预测 → 地图/定位 → 行为决策 → 运动规划 → 控制。
   → 用法：不是从头读到尾，而是"我下一步要动哪块时来这里查它的邻居是谁"。

## 四、这套材料与你仓库的"缺口对照"（一页速览）

| 环节 | 业界标准做法 | 本仓库现状 | 缺口性质 |
|---|---|---|---|
| 时间同步 | 传感器时间戳 + 硬件同步 | 固定步长总线（`js/sim/engine.ts`） | 未做（S5） |
| 检测 | 3D 框 / 语义 | 单线 LiDAR 聚类（`js/algo/objects.ts`） | 简化（学习用途合理） |
| **跟踪** | EKF/UKF/**IMM** + 匈牙利/JPDA + **协方差** | α-β + 最近邻 + 计数确认，**无协方差** | **可补，收益直接** |
| **车道归属** | 车道多边形 + 物体框 + 不确定性 + 迟滞 | 逐点 Frenet 投影 + 阈值（已改逐段投影） | **半补：投影已修，归属仍是几何式** |
| **预测** | 每物体 3~8s 多模态轨迹 | **无** | **最大代差** |
| **责任划分** | RSS / 路权 / 切入检测 | 走廊膨胀 + 裕度标定表（近似） | **缺语义层** |
| 规划 | 横纵解耦 + 迭代（EM/lattice） | SL/ST 解耦 + ≤3 轮收敛迭代 | 基本对齐 ✓ |
| 控制 | MPC / 纯跟踪 + 安全兜底 | Pure Pursuit + 油门目标 | 对齐 ✓ |
| 验证 | 影子模式 + 场景库 + 按里程指标 | `runs/` 归档 + 检测器 + 同种子 A/B | **雏形已有，指标未固化** |

## 五、使用约定

- 六个专题文档里的**每条链接都经过核实**；确实核实不了的会显式标注 `（链接未核实）`。
- 每篇末尾都有**可落地的最小练习**（几小时量级 + 可量化验收判据）——建议按"练习"而不是"读论文"推进，
  读完立刻在本仓库做一次 A/B，把数字写进 `docs/domain.md` 或 `CLAUDE.md` 的对应条目。
- 仓库的活文档仍是权威：`docs/domain.md`（问题图鉴）、`CLAUDE.md`（架构与约定）、
  `ISSUE_HISTORY.md`（历史决策）。本目录只负责"对标业界"，不重复记录项目决策。
