- 关联：

## 1. 背景与目标

**动机**：解耦规划器已达批量 0 碰撞 / 8-10 到达，但本会话的逐帧钻取暴露三类**结构性问题**（参数调优已证明治不了，见下方负结果）：

1. **二元阈值 + 离散横向候选 → 临界抖动（knife-edge）**：紧间隙场景中，路径到障碍的最小间距在安全阈值附近抖动（实测 3 帧内 1.44m → 1.14m，跨越 HARD_CLEAR=1.4m），"慢行通过"与"封死→紧急制动"随之翻转，且缺少迟滞与记忆。
2. **标称几何余量不建模执行误差**：安全裕度是常数 0.4m，而实际可达到的余量随速度与曲率下降（大角度低速转弯时跟踪误差显著大于直行）——规划"几何可过"（标称间距 1.8m）而闭环实测擦挂。
3. **路径先定、速度后算（顺序解耦）在窄口失效**：通过性本质依赖速度（发展段随 v² 缩放），顺序单轮传递丢掉了反馈 → 停车后死锁（v=0 时唯一可行速度被自己的参数化封锁）。

**负结果（已实验证伪，勿重复）**：

- 发展段下限 12m → 6m / 3m（单场景 hairpin-s8）：看似解锁，实测引入接触（4776 / 4719 帧，车贴着障碍磨停）；
- 紧间隙限速 8 → 3 m/s（单变量，全批 A/B）：丢 2 个到达、多 1 段碰撞、部分变慢；
- 低速预瞄 10m → 4m：无改善（否定了"纯追踪切弯"假设）。

**验收总标准**：每阶段独立批量 A/B——碰撞 **0 段/0 帧不劣化**、到达率与**到达用时/路线进度不劣化**（三者合读）；阶段专属指标见各节。架构目标：横向决策从"离散候选 + 二元阈值"演进为"走廊 + 连续代价"，裕度从常数演进为误差感知，路径-速度从顺序演进为迭代收敛。

## 2. 范围

**包含**：`paths.ts` 的走廊化重写（阶段 A）；走廊膨胀的误差感知裕度与迟滞状态机（阶段 B）；`planner.ts` 的路径-速度迭代协调（阶段 C）；各阶段配套单测、批量 A/B、文档更新。

**非目标**：

- 不改 `Trajectory` 输出契约、速度层 ST 接口（`STObstacle`/`SpeedMode`）、`states.ts` 对外语义；
- **不引入 QP 优化器**（阶段 A 用密集采样；QP 作为将来的独立演进）；
- **不做倒车/多方向机动**（依赖障碍物理实体，属已缓办的独立决策）；
- 不动感知（`perception.ts`）与控制（`control.ts`）层；
- 走廊必须由 LiDAR 命中构建（传感器驱动原则），禁止引用障碍物真值列表。

## 3. 阶段 A：走廊化横向表示（corridor-based lateral representation）

### 3.1 走廊构建（corridor construction）

- **输入**：现有命中点 + 命中链段（与当前阻塞判定同源，`lidarScan` 派生）。
- **投影**：每个命中点/链段端点投影到 Frenet（s, l）。链段按端点投影的 (s, l) 区间表示（投影非线性带来的近似误差由既有距离函数在验收测试中校准）。
- **膨胀**：按（车半宽 + 裕度）向两侧膨胀为阻塞区间；**舒适走廊**用常数裕度 1.5m、**物理走廊**用 0.4m（阶段 B 把后者换成 `margin(v, κ)`）。
- **求自由区间**：对每个纵向采样点 s（沿用 PATH_STEPS 网格），把落在 [s−Δ, s+Δ]（Δ 为链段沿 s 半长）内的阻塞区间取并集，在 [−L_MAX, L_MAX] 内求补集；无命中 → 全宽。
- **输出**：`corridor: { s, free: [lmin, lmax][] }[]`（同一 s 可有多个自由段）+ 瓶颈信息（窗口内最窄处的自由段）。

### 3.2 双走廊 = 双阈值的新形态

原 CLEAR / HARD_CLEAR 的层级语义保留，但载体从"逐命中距离阈值"变为"两条走廊"：

- 候选**舒适阻塞** ⇔ 路径越出舒适走廊（用于横向排名，晚承诺窗口 60m 内）；
- 候选**物理阻塞** ⇔ 路径越出物理走廊（全程 120m，决定停车线）；
- 全部候选物理阻塞 → 触发停车（沿用现有停车线/可达性闸门逻辑）。

### 3.3 候选派生（由走廊出发，替代固定档位）

在**提交窗口内走廊最窄处（瓶颈）**取自由段：优先取包含车道中心（或离当前 l0 最近）的自由段，其次其余自由段（最多 2 段）。每个自由段内密集采样候选目标：**段中点（间隙中心）+ 以 0.5m 间隔向两侧铺开（每段 ≤3 个）+ 段边界内缩 0.3m**；另保留"车道中心（若自由）"。目标总量 ≤7，clamp 去重沿用。间隙中心天然被覆盖（治"候选打不中缝隙中心/被迫贴边"两类旧疾）。

### 3.4 代价（cost）

沿用 `W_PATH_CENTER / W_PATH_CURV / W_SWITCH_PATH`，新增**贴边惩罚（edge penalty）**：

```
cost += W_EDGE · Σ_i max(0, 0.5m − dEdge(s_i))²
```

`dEdge(s)` = 路径到该 s 处自由段边界的距离（物理走廊）；平滑、仅贴边 0.5m 带内生效，与"间隙中心偏好"一致。

### 3.5 不变项

两段式发展段与自适应逻辑、提交窗口（60m）、ST 合成、轨迹输出、状态机。

### 3.6 阶段 A 验收

- 单元：走廊构建（含急弯/hairpin 投影）；间隙中心候选存在性（oval-s2 类场景的走廊中心必被采样覆盖）；越出走廊 ⇔ 阻塞（与旧判定的对拍测试）；
- 批量（种子 6-10）：**0/0 不劣化、到达 ≥8/10、用时/进度不劣化**；oval-s2 类"贴边复位"回归保持 0；
- **不设** hairpin-s8 通过性指标（执行层问题，属 B/C）。

### 3.7 风险与缓解

Frenet 投影近似在急弯的精度 → 与现有距离函数做对拍测试，偏差超阈值则以笛卡尔距离兜底复核；候选数上限 7 与现状同量级 → 性能不劣化（记录单轮耗时）。

## 4. 阶段 B：误差感知裕度 + 迟滞（error-aware margin + hysteresis）

### 4.1 裕度标定（归档数据驱动）

- **数据**：现有 `runs/` 归档的 frames——每帧提取（速度 v、轨迹曲率 κ、横向跟踪误差 e）。e 的定义沿用检测器的 tracking_error 口径（车到上一帧规划轨迹的横向偏移）；κ 由轨迹 yaw 变化率 / 速度得到。
- **方法**：按 (v, κ) 分箱取 e 的 95 分位 → 拟合 `margin(v, κ) = m₀ + k·κ·v²`（横向加速度项形式）；系数 clamp 到 [0.4m, 1.2m]。
- **交付**：标定脚本（headless 工具，可复跑）+ 标定报告（样本量/分箱覆盖/拟合系数/留出集覆盖率）。
- **集成**：仅作用于**物理走廊**膨胀（舒适走廊保持常数）；接口预留为函数 `marginFor(v, κ)`。

### 4.2 迟滞状态机（TightState）

```
TightState = NONE | CREEPING | SEALED
```

- **进入 SEALED**：全部候选越出"物理走廊 **−** 额外收缩 0.15m"（即**更松**的走廊也过不去 = 确实过不去）
  ——注意方向：进入用更松、退出用更严（标准施密特触发；§4.2 初稿写反，2026-09-25 实现时纠正）；
- **恢复**：存在候选在（未收缩的）物理走廊内 → 退出 SEALED；
- **CREEPING**：存在物理可过但舒适阻塞的候选（即现行紧间隙慢行档）；
- **时间防抖**：任何状态切换需连续 3 帧（≈50ms）一致才生效；转移表与最短保持时间全部单测覆盖。
- 原"停车线 + 可达性闸门"逻辑在 SEALED 状态下照常工作；临界带内因空间带 + 时间防抖不再翻转。

### 4.3 阶段 B 验收

- 单元：临界带（间距在阈值 ±ε 抖动）内状态不翻转；转移表/防抖全覆盖；
- 标定：留出集覆盖率 ≥95%（实测误差被 margin(v,κ) 包住的样本占比）；
- 批量：0/0 不劣化、到达与用时/进度不劣化；抖动类场景（hairpin-s7 类）**紧急制动次数下降**。

### 4.4 风险与缓解

标定数据的曲率/速度覆盖不足 → 补充脚本化机动场景（不同速度 × 曲率的受控机动）专门采集；裕度变大会否降低通过性 → 以批量到达率/进度为判据，超限则收紧 clamp 上界。

## 5. 阶段 C：收敛判据迭代（convergence-criterion iteration）

### 5.1 交替结构（EM 风格）

每帧规划内：

```
v ← 当前纵向速度（clamp 到 vCap）           # 初始假设
repeat（最多 3 轮）:
  路径层（用 v 决定裕度 margin(v,κ) 与发展段） → 路径 P_k（目标横向偏移 a_k）
  速度层（用 P_k 的几何：停车线/紧间隙/可过性） → 速度上限 u_k
  若 |a_k − a_{k−1}| < 0.2m 且 |u_k − u_{k−1}| < 0.5 m/s → 收敛，退出
  否则 v ← u_k，进入下一轮
兜底：取最后一轮结果（确定性；收敛率进归档指标）
```

层间传递量固定：路径→速度 = {停车线弧长、走廊/阻塞几何、紧间隙标记}；速度→路径 = {速度假设 v（决定 margin 与发展段）}。

### 5.2 性能与确定性

- 预算：单轮路径层实测 <1ms（15Hz 规划）；实现时加**轮次耗时断言**（单帧规划总耗时 <5ms，超时记录）；
- 确定性：迭代为纯函数链，同输入同轮数（收敛判据含"变化不降反增则提前停"，防极限环）。

### 5.3 阶段 C 验收

- hairpin-s8 类窄口：**不再死锁**——要么干净通过、要么给出干净的停车判定，**不得引入接触**（0/0 碰撞保持）；
- 批量：到达率与用时/进度不劣化；新增归档指标"需 >1 轮的帧占比"（收敛率）与"单帧规划耗时";
- 若 C 后窄口仍无法安全通过：如实记录为**能力边界**（不引入倒车；倒车依赖障碍物理实体决策），并在 `docs/domain.md` 更新结论。

## 6. 跨阶段纪律与交付

- **一阶段一循环**：每阶段走 writing-plans → TDD 实施 → 批量 A/B → 负结果入库；**上一阶段验收通过后才启动下一阶段**（单变量，避免叠加归因困难）。
- **不变量**：Trajectory 输出契约；ST 接口；传感器驱动（走廊只吃 LiDAR 命中）；同种子逐帧确定性（批量 A/B 基础）；所有阈值/系数以 `m()`/`mps()` 书写。
- **文档**：每阶段完成后更新 `CLAUDE.md` 规划器章节与 `docs/domain.md` 相关条目。
- **回滚**：以提交为单位原子替换；批量劣化即回滚并记录负结果（沿用本会话纪律）。

## 7. 开放问题

1. 走廊在复杂几何下的取舍规则（同一 s 多个自由段、环绕式障碍）——先按"含车道中心/最近者优先、最多 2 段"实现，A/B 定夺是否调整；
2. 标定数据的曲率覆盖度——视 4.4 的补充采集结果定；
3. hairpin-s8 类窄口的最终归宿（C 之后仍不能安全通过时记录边界 vs 未来引入倒车）——依赖 P10（障碍物理实体）的决策。
