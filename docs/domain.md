## 0. 架构背景

规划器为**纵向-横向解耦（longitudinal-lateral decoupled planning）**：SL 路径层（`js/algo/plan/paths.ts`）决定"走哪条"（横向偏移 l(s) 曲线，120m 视程纯几何碰撞检查），ST 速度层（`js/algo/plan/speed.ts`）决定"什么速度"（巡航/停车线/紧急），规划器单轮协调后按 l(s(t)) 合成轨迹（Trajectory）。下方问题的编号 P1～P11 在本仓库的被引用惯例即指本文条目。

## 1. 规划决策类

### P1 提前承诺（early commitment）→ 死口袋（dead pocket）

**现象**：障碍还在几十米外时规划器就选定侧向避让路径；随后另一障碍封死该侧 → 车进入无出口死角，低速紧急爬行（碰撞帧被放大 70-100 帧）。

**来龙去脉**：解耦升级把路径视程扩展到 120m 纯几何视程后，直接把全程阻塞信息用于候选排名——"看到"与"承诺"被混为一谈。

**根因**：视程长 ≠ 决策应早。过早承诺牺牲后续灵活性。

**技术方案**：提交窗口（commit window）`COMMIT_WINDOW = 60m`——横向排名只看窗口内阻塞（晚承诺）；停车线判定仍看全程（纵向保守）。同一份感知按用途分两个时域消费。

**验证**：同种子 A/B，hairpin-s5 帧数 69 → 38（后续归零）。

**领域教训**：感知应尽量远、承诺应尽量晚——两者是独立参数，不能共用一个视程。对应现实中的"变道时机"决策。

### P4 过保守判停（over-conservative stopping）→ 场景卡死（parking）

**现象**：以舒适间隙判"封死"导致 6/10 场景永久停车，其中两处旧规划器干净通过（可行路线存在）。

**根因**：单一安全阈值无法同时表达"顺不顺"与"能不能过"——必然在过度保守与冒险间摇摆。

**技术方案**：双阈值（two-tier clearance）——**舒适走廊**（车半宽 + `max(1.5m, 标定 p95)`）只影响排名与"要不要慢行"；**物理走廊**（车半宽 + `marginFor(v)`，2026-09-25 起为标定速度表）决定停车线；更严/更松走廊（±0.15m）供迟滞状态机（`tight.ts`）做封死的进入/退出。全部候选连物理走廊都过不去才停；存在物理可过候选则**限速 8m/s 慢行**（紧间隙模式）。另有**可达性闸门（reachability gate）**：目标速度与当前速度的制动距离不足则诚实降级为紧急制动（2026-09-25 起用"当前速度档几何"判，避免收敛迭代在低速假设下误判可达）。

**验证**：批量卡死 6/10 → 2/10；负结果在案（舒适间隙降到 1.5m 使两场景变成"停车时仍在碰撞区"，回滚）。

**领域教训**：安全策略应分级（分级阈值 + 分级行为）；"能过但要慢"是真实驾驶的常见状态，需要对应的行为档。

### P5 固定发展段（fixed development）来不及展开 → 假阻塞（false blockage）

**现象**：障碍只占两个车道、左右各有可通过空间，规划器却停车（hairpin 种子 7 实测：S=122.3m 处停下）。

**来龙去脉**：障碍在车前 20.8m、横向占 l∈[−1.6,+2.0]；右侧物理可过带 l∈[3.4,4.4]。时间线：障碍 50m 外时 −4.4m 候选完全展开且单车道畅通（规划器正确选中）→ 车在右侧 l≈3.9 需 8m 横移 → 障碍进入 32m 内后，固定 40m 发展段的路径在障碍处才横移一半 → 曲线本身穿过障碍带 → 判阻塞 → 全部候选死亡 → 停车。

**根因**：固定长度的机动段隐式限制了可达行为；阻塞判定判的是**实际曲线**而非终点目标；"来不及机动"是运动学约束（kinematic constraint），不是逻辑错误。

**技术方案**：自适应发展段（adaptive development）——首个阻塞落在发展段内时，缩短发展段到阻塞点前（留 6m 余量、下限 12m）重新生成重检；**运动学下限随速度平方缩放**：峰值横向加速度 = `5.77·|Δl|·v²/S² ≤ 3.5 m/s²`（高速不许幻想急横移，低速才允许紧间隙急机动）。

**验证**：停车帧恢复物理可过候选；批量到达 5/10 → 8/10，碰撞保持 0/0；高速行为零回归。

**领域教训**：路径/轨迹的参数化方式**本身**就是能力边界；速度依赖的机动约束必须在规划时显式建模，否则要么停死、要么输出不可跟踪（untrackable）的轨迹。

### P3 走廊边缘候选 + 越界复位传送（teleport reset）

**现象**：车贴走廊边缘漂移 → 越过复位阈值 |l|=5.0 → 环境把车传送回中心线 → 落在障碍正前方 → 连锁碰撞（3134 帧）。

**两个子根因**：
1. 候选稀疏：唯一"清晰"候选是走廊边缘（距复位崖仅 0.6m 余量），真正可通过的间隙中心（约 −3.1m）没有候选 → 候选集增加 ±5m 挪移档；
2. 贴边棘轮：五次多项式为满足初值斜率先向端点外下沉，逐帧重读当前位置使下沉累加（l 从 −4.4 滑到 −4.93）→ 横向路径夹紧 [l0, target]。

**领域教训**：候选采样要覆盖**间隙中心**而非固定档位；逐帧重规划（receding-horizon replanning）中任何端点外过冲都会累积成棘轮；**复位/传送是危险动作**——把车放到未经规划的状态比不放更危险。

### P12 窄口余量 < 执行误差预算（capability boundary）

**现象**：批量（种子 6-10）中 6/10 场景在窄口前**干净停车**（DECEL、v=0、零接触、零紧急制动），
任务不完成；同一批缝隙在早期版本（几何余量 0.4m）能过但会发生接触（oval-s9 2908 帧、hairpin-s9 4712 帧）。

**根因**：这批场景的障碍（3.3~4.9m 宽）在 8.8m 车道里只留 **0.6~0.95m 车身余量**；而标定实测
横向跟踪误差 p95 在慢行档 = **0.91m**（低速段到 1.15m，`docs/margin-calibration.md`）。
"能过"与"安全"在同一裕度下互斥：预算调小 → 敢过但接触；预算照实 → 判死但干净。

**次要成因（2026-09-25 复核：归因需分三类，勿混为一句"窄口太小"）**：
1. **合法通行带极窄**（真能力边界）：oval-s7 窗口最窄自由宽 0.26m、oval-s9 0.02m —— 裕度吃掉了几乎全部余量。
2. **候选锚定单一瓶颈（single-pinch anchoring）→ 双瓶颈异侧不可达**：hairpin-s9 实测——30m 处瓶颈只留左侧
   1.35m 自由带、72m 处另一障碍只留右侧 4.0m，两瓶颈之间（36~66m）**整幅自由**；但候选只从"最窄那一步"
   （pinch）派生（三个目标全在左侧）→ 三条路径全部在 69m 处撞上第二个障碍 → `allBlockedHard` → 封死停车。
   车眼里的"又长又宽的缝"正是这段过渡区，而**单目标五次多项式路径表达不了"先左后右"**。这与裕度无关，
   属可修的能力缺口（候选需跨多个瓶颈 / 走廊内连续搜索，即 A2 方向）。
3. **封死记忆与可达性闸门交互**：hairpin-s7（停滞点 `allBlockedHard=false`、最左候选畅通却仍停车）——
   机制待单独钻取。

**技术方案（本次）**：不调参换通过率——按 spec §5.3 记为能力边界；把"到达率"换成了
"零接触 + 零紧急制动 + 干净停车"（全分支评审修掉一处"裕度单位混用致标定表失效"的 Critical
后复跑，结论不变：4/10 到达、0 接触、0 紧急制动）。真正的出路是**把误差预算本身压下来**（轨迹形状稳定化：
实测 p95 尾部 5% 帧的 ~1m 偏离来自规划轨迹逐帧形状变化，与机动/速度无关——见标定报告第二轮分析）
或**候选准入/横向承诺**（不该去的位置不去）。

**领域教训**：安全裕度是"规划可执行性"的度量，不是调参旋钮。当场景几何进入误差预算之内时，
正确的产品行为是"停下来"而不是"过过看"——这也是真实自动驾驶保守式部署（ODD 限制）的由来。

### P13 HD Map 背景减除的固有盲区：遮挡阴影被当成"自由"

**现象**（2026-09-25 由走廊可视化首次暴露）：走廊/带子渲染的范围超出激光雷达**真正看到**的范围。
hairpin-s9 实测：走廊画到 92m（= 路线剩余），而沿道路中心线的视线覆盖极限只有 **≈70m**——
更远处的射线（方位 38~43°，仍在 ±60° 视锥内）已在 **18~27m** 处被弯道内侧墙/前方障碍吸收。

**根因**：背景减除把道路边界的命中从规划器输入中剔除（|l|≥6m → 替换为 MAX_SENSOR_DIST），
所以**墙/障碍投下的阴影区在走廊里没有任何阻塞体** → 走廊补集逻辑把"没检测到"当成"自由"
（"看不到 ⇒ 没障碍"）。这是 HD Map 式感知的固有盲区，不是渲染缺陷。

**技术方案（本次 = 可视化层）**：走廊带按"本帧是否被真正扫到"分色——判据 = 存在方位夹角 ≤ 半格
且**射线长度 ≥ 到车距离**的射线（必须用 `rawDistances`，含边界；用规划用的 `distances` 会得出
"墙后也算观测过"的反结论）；未观测区画灰蓝（"未知"不等于"自由"），并在覆盖极限处画横断线。

**规划层实验（2026-09-25，`paths.ts` 的 `UNKNOWN_HANDLING` 开关，批量 10 场景实测）**：
- `'blocked'`（未观测 = 不可通行，即字面口径）→ **退化**：规划视程 120m 恒大于可见距离（≈70m），
  所有候选都在可见边界外"硬阻塞" → 封死 → **10/10 场景停在 1% 进度**（0 碰撞但车根本不动）。
  教训：无人驾驶**必须**规划到未观测区（否则永远无法前进），差别只在于"以多大代价进入"。
- `'speed'`（见-即-停限速 v ≤ √(2·A_BRAKE·d_vis)，不裁几何）→ 0 碰撞、到达率不变（4/10），
  进度：hairpin-s9 59→**67%**、oval-s9 59→**61%**（改善），hairpin-s8 71→**64%**、hairpin-s6 用时
  11.6→**12.2s**（代价）——即"遮挡处减速"的安全-效率权衡，非免费改善。
- 默认仍为 `'free'`（旧行为）；是否采用 `'speed'` 及其力度（A_BRAKE vs 舒适减速度）待定。

**领域教训**：感知的"未检出"与"不存在"必须在数据模型里分开表达（occupancy 的 unknown 态）。
可视化是把这类建模缺口逼出来的最便宜工具——这次是用户看图问出来的。

## 2. 感知与状态估计类

### P6 感知参考线缓存不失效 → 规划器"失明"

**现象**：浏览器实时仿真中小车**稳定穿过障碍物**；回放同场景归档（headless 生成）无碰撞。

**来龙去脉**：HD Map 背景减除（background subtraction）依赖一条地图参考线做命中点投影与 |l| 三级分类（<4.5m 障碍 / <6m 边缘模糊 / ≥6m 边界清除）。该参考线模块级只建一次：headless 每进程新世界 → 正确；浏览器同进程切换地图 → 感知仍用**旧地图**中心线 → 障碍命中 |l| 算成 100m 量级 → 全判为边界过滤 → 规划器看到空路。

**证据**：同进程"先 oval 再切 hairpin"复现 49 帧碰撞；全新进程 0 碰撞；修复后逐字段一致。

**技术方案**：参考线缓存按**对象身份失效**（track/route 对象变化即重建）；路线缓存键从"起始终点索引"（跨地图重名）改为对象身份。

**领域教训**：HD Map 依赖型感知的正确性完全取决于地图假设——地图错了，感知是**系统性错误**（把障碍当边界清除）而非降级。这类缺陷只在长生命周期进程（真实车机的地图切换/热更新）暴露，是量产系统的更高优先级问题。

## 3. 数值与状态机健壮性

### P7 停车后 NaN 轨迹污染（NaN pollution）

**现象**：回放 HUD 崩溃 `Cannot read properties of null (reading 'toFixed')`。

**来龙去脉（三层掩盖）**：停车线剖面时长 `T = 2·sStop/v0`，车停住后 v0=0 → T=Infinity → 五次多项式 NaN → 每帧 NaN 轨迹 → steerAngle/control 全 NaN → `JSON.stringify(NaN)` → **null 落入归档**（3000-4900 帧）→ 回放才崩。

**技术方案**：v0 < 1u/s（已停住，与控制层停车阈值一致）→ 静止零剖面；HUD 对旧归档空值显示 `---`。

**领域教训**："停车"是规划器的常态目标状态而非边界情况——所有除以速度的公式在 v=0 处都要单独定义；注意 NaN 被序列化（JSON/日志/SQL）静默改写为 null，容易断线排查。

### P8 贴边棘轮（edge ratchet）数值漂移

见 P3 子根因 2。**教训**：逐帧以当前位置重规划时，路径生成必须显式约束"不越出端点"。

## 4. 车辆动力学与控制接口

### P2 停车语义（stop semantics）被控制层怠速下限架空

**现象**：批量碰撞中 5/7 段的速度恒为同一常数 6.4 m/s（=0.15×42.5，油门怠速下限×最大速度）。

**来龙去脉**：规划层输出"减速到 0"剖面；控制层油门 `max(0.15, 终点速度/maxSpeed)`（历史"防完全停车"防御 hack）把停车翻译成 6.375m/s 恒速爬行——车慢慢爬进障碍、长时间保持接触。

**根因（接口层）**：控制-规划接口把轨迹的时间维**降维成单一标量**（只取终点速度）——规划层精心构造的速度剖面到执行层只剩一个数字，任何"下限/兜底"都会在该单点静默改写规划意图。

**技术方案**：终点速度 < 1u/s → 油门 0；正值目标保留怠速下限。

**领域教训**：执行层不能有隐式默认行为覆盖规划意图；保护性逻辑应由规划器通过显式接口表达（如驻车意图标志），而不是全局下限替所有轨迹做主。

### 动力学约束（制动与机动）

两条决定"能不能停/能不能让"的约束方程：
- 制动距离（braking distance）`d = v²/(2a)`（本项目最大减速度 8m/s²：30m/s 约 56m；保守形状口径约 70m）；
- 峰值横向加速度 `5.77·|Δl|·v²/S²`（S = 完成横移的纵向距离）。

**教训**：可行性判断必须建立在运动学上——"看起来能过"不等于"能让得开"。

## 5. 测试环境与场景生成

### P9 出生点净空（spawn clearance）与起始速度

**现象**：新随机种子出现两类灾难样本——障碍生成在出生点 3.05m 处（初始即重叠，全场 3600 帧碰撞，与速度无关）；25m/s 起步 + 前方 13.8m 障碍（制动需 52m，任何规划器不可避）。

**技术方案**：生成器加出生区净空（沿弧 ≥80m，精确环形弧长判定）；默认起步速度 25 → 5 m/s（可覆盖）。

**领域教训**：**"物理不可避"的样本是无效测试数据**，会污染评测结论；评测前应做场景可解性检查；起始条件（速度/朝向/净空）必须与车辆能力（制动/加速）匹配——对应真实系统的启动自检。

### P10 障碍物无物理实体（no solidity）

**现象**：碰撞后车直接穿过障碍（环境物理不查询障碍物）；停死后不能倒车（无倒挡模型）。

**后果**：观测混淆（真缺陷与常态"穿过"难区分——P6 就曾被误认）；停死场景不可恢复；评测帧数被停留放大。

**待办（缓办）**：① 物理阻挡（MTV 推出 + 法向速度消除，推荐）② 碰撞后复位 ③ 立即停止仿真——均改变评测语义，需单独设计。

## 6. 评测方法纪律

### P11 指标成对读

- 碰撞**段数**（发生几次）与**帧数**（接触持续）必须一起读：低速蹭行使帧数按时间放大（6.4m/s 爬行一段 ≈ 40 帧）；
- **"零碰撞"可由"卡死不动"换到**：碰撞数与到达率必须合看；
- **同种子确定性（determinism）是根因定位的地基**：逐帧一致使复现/对照/重放/回归全可行（连 UI 重构是否影响仿真都能一秒确认）；
- **负结果入库**：失败的实验同样记录（如舒适间隙 1.5m 实验），避免重走弯路。

## 7. 遗留问题

| 优先级 | 事项 | 说明 |
|---|---|---|
| 高 | 6/10 场景干净停车（P12，混因） | 三类：真能力边界（合法带 0.02~0.26m）、候选锚定单一瓶颈（chicane 不可达）、封死记忆交互；后两类可修（见 P12） |
| 高 | 候选需跨多个瓶颈（A2 走廊内连续搜索） | 单 pinch 派生 + 单目标五次多项式表达不了"先左后右"；走廊已在手，DP/QP 一次解出 l(s) 即可覆盖 |
| 高 | 轨迹形状稳定化 | 标定第二轮：p95 尾部（5% 帧 ~1m 偏离）与机动/速度无关，源自规划轨迹逐帧形状变化 → 压低它的收益同时覆盖 P12 与"晚承诺"抖动 |
| 中 | 场景集校准 | 障碍宽度 3.3~4.9m + 8.8m 车道 → 缝隙常低于车宽+裕度；批量应同时含"可通行"与"应停车"两类，避免门禁被不可行几何主导 |
| 中 | 障碍物理实体（P10） | 影响观测、恢复与评测语义 |
| 中 | 倒车/脱困（recovery） | 停死场景无出路，依赖 P10 设计 |
| 低 | 评测报告固定输出"段数/帧数/到达率"三件套 | 防单指标误读 |
