# incidents/ —— 缺陷档案目录（一事一档）

单个问题的完整根因分析落在这里：**一事一档、可被引用、状态可更新**。
与 `docs/domain.md`（跨问题的领域知识，持续增补）和 `ISSUE_HISTORY.md`（总台账，一行一条）分工。

## 命名

- 缺陷：`YYYY-MM-DD-<kebab-slug>.md`（如 `2026-09-24-stale-frenet-ref-cache.md`）
- 架构决策：暂并入本目录，标题前缀 `[决策]`（如 `[决策] 双阈值间隙与停车线.md`）；数量多了再拆出 `docs/decisions/`

## 每份文档的头部四行（统一模板）

```markdown
# <标题：现象一句话>

- **日期**：YYYY-MM-DD
- **状态**：复现中 / 已修复 / 已被 <文档> 取代
- **关联**：commit 哈希、场景文件、测试路径（可双向引用：代码注释里也回指本文档）
- **结论**：一句话根因
```

## 什么时候写

- 出现"值得留档"的缺陷（根因非显而易见、或会复发、或影响评测结论）时；
- 修复完成后在 `ISSUE_HISTORY.md`（总台账）追加一行：日期 + 一句话 + 链接到本目录文档；
- 老记录（`ISSUE_HISTORY.md` 中已成型的历史条目）不搬迁，作为台账历史区保留。

## 与其它文档的关系

- 设计规格 → `docs/superpowers/specs/`
- 实施计划 → `docs/superpowers/plans/`
- 会话/里程碑复盘（冻结快照）→ `docs/reports/`
- 领域坑图鉴、术语表（活文档）→ `docs/domain.md`
